## 📌 Обзор проекта

Приложение создано для автоматизации ресторанов, кафе и служб доставки, использующих интернет-магазин на базе WooCommerce (WordPress).

- **Принтер 1 (Касса/Пречек, ~58 мм):** USB-принтер **XPrinter XP-N160II** (XP-58C). Формирует накладную / пречек со списком позиций (Наименование, К-во x Цена = Сумма), реквизитами продавца, адресом доставки и итоговыми суммами.
- **Принтер 2 (Кухня, ~80 мм):** Сетевой IP/LAN-принтер **XPrinter XP-80T** (XP-80C). Формирует кухонный чек с крупным временем заказа, типом доставки и списком блюд/товаров.
- **Опрос сайта:** Фоновый цикл опроса WooCommerce REST API (`/wp-json/wc/v3/orders?status=processing`) с настраиваемым интервалом от 1 до 5 минут.
- **Автопечать:** Автоматическая отправка на печать при поступлении новых заказов без облачных посредников.
- **Генерация PDF:** Параллельное формирование PDF-копий для предпросмотра и архивации.

## 🔍 Разбор ошибок ветки `mariettka` (почему возникали)

В ходе аудита ветки `mariettka` были выявлены следующие ключевые ошибки и причины их возникновения:

### 1. Ошибка вывода позиций в кастомном чеке (несоответствие default шаблону)
- **Причина:** В методе `BuildTemplateLines` блок `block.items` просто итерировал товары и для каждого вложенного поля отдавал пару `(child.Name, value)`. При печати через GDI (`BuildTemplateTextLines`), ESC/POS (`BuildTemplateEscPos`) и в PDF (`ExportTemplatePdf`) это приводило к построчному выводу вида:
  ```text
  Наименование: Пицца
  Кол-во: 2
  Цена: 15.00
  Сумма: 30.00
  ```
  вместо структурированной таблицы с заголовком и колонками как в накладной по умолчанию.
- **Решение:** Добавлен параметр `ItemDisplayMode` ("Table" / "Kitchen" / "List"). В режиме `Table` блок товаров автоматически верстается в структурированную таблицу (Наименование на первой строке, ниже выровненные по колонкам `К-во шт x Цена  Сумма`, окруженные разделителями) в точности как во встроенном default-шаблоне.

### 2. Невозможность удаления полей в блоке вывода заказов и в списке
- **Причина 1:** В WPF `ListBox` клик по внутренним элементам строки (TextBox, ComboBox, Border блока `block.items`) перехватывал фокус ввода, но **не менял** `SelectedIndex` у `ListBox`. Кнопка «❌ Удалить поле» на правой панели считывала `LstReceiptFields.SelectedIndex` (который оставался `-1` или указывал на ранее выделенный чужой элемент), из-за чего удаление не срабатывало или удаляло не то поле.
- **Причина 2:** У самой карточки поля не было кнопки удаления на строке.
- **Причина 3:** Для подполей в `block.items` обработчик `BtnRemoveSubField_Click` искал объект через `parent.ChildFields.Remove(subField)`, что могло давать сбой при редактировании или отсутствии проверки вхождения.
- **Решение:**
  - Добавлена индивидуальная кнопка «❌» непосредственно в правый угол каждой строки поля (`BtnRemoveFieldItem_Click`). Теперь любое поле (включая весь блок `block.items`) удаляется в один клик.
  - Каждое подполе внутри `block.items` оснащено надежной кнопкой удаления с проверкой `Contains`.
  - Кнопка удаления на правой панели теперь безопасно проверяет как `SelectedItem`, так и `SelectedIndex`.

### 3. Отсутствие настроек пунктирных разделителей и отступов между строками
- **Причина:** Модель `ReceiptField` содержала только базовые свойства `Name`, `Key`, `FontSize`, `IsBold`, `Align`. Не было возможности вставить горизонтальный разделитель (пунктир, сплошную, звездочки), задать пустую строку или настроить вертикальный интервал.
- **Решение:**
  - В модель `ReceiptField` добавлены свойства `IsSeparator`, `SeparatorStyle` ("Dashed", "Solid", "Dotted", "Stars", "Double"), `LineSpacing` (отступ снизу в pt), и `IsRow` (вывод в 2 колонки: метка слева, значение справа).
  - В `MainWooCommerceOptions` добавлены опции:
    - `separator.dashed` — пунктирная линия
    - `separator.solid` — сплошная линия
    - `separator.stars` — строка звёздочек `***`
    - `separator.double` — двойная линия `===`
    - `space.empty` — пустой отступ (интервал)
  - На панели добавлены кнопки быстрой вставки: «➕ Пунктир» и «␣ Пустой отступ».

### 4. `NullReferenceException` при тестовой печати
- **Причина:** В `PrintingService.PrintTestPageAsync` вызывался метод `_documentBuilder.BuildFormLines(PrintFormType.TestPage, null!, width)`. При определенных ветвлениях или пустом шаблоне метод обращался к свойствам переданного `slip`, что приводило к сбою.
- **Решение:** В `BuildFormLines` добавлена строгая проверка на `null` с безопасным фоллбеком на `BuildTestPageLines`.

### 5. Ошибка доступа `UnauthorizedAccessException` при сохранении PDF-копий
- **Причина:** В `PrintingService` путь сохранения предпросмотра чеков `check_{id}.pdf` и тестов формировался через `AppContext.BaseDirectory`. Если приложение установлено в системную папку (например, `C:\Program Files\...`), запись туда блокируется Windows UAC.
- **Решение:** Метод сохранения PDF переведен в безопасную пользовательскую папку `%AppData%\PrintingSlips\PdfExports\`, с перехватом исключений, чтобы сбой файловой системы никогда не блокировал печать на физическом принтере.

### 6. Обрезка нижней части чека в `WindowsQueuePrinter`
- **Причина:** `MeasureHeight` рассчитывал высоту по идеальной ширине без учета аппаратных непечатаемых полей драйвера (`HardMarginX`, printable area margins). Когда драйвер сжимал ширину печати, длинные строки переносились на большее количество строк, высота чека превышала расчетную, и при жестко заданном `e.HasMorePages = false` подвал чека обрезался отрезчиком.
- **Решение:** Добавлен 15% запас высоты и дополнительный буфер 80 единиц (1/100 дюйма) для гарантированного выхода чека под отрезчик.

## 🚀 Что было исправлено и улучшено

| Компонент | Было | Стало |
|---|---|---|
| **Вывод позиций `block.items`** | Построчные пары `Наименование: X, Кол-во: Y` | **Полноценная таблица** как в default накладной (Наименование, К-во x Цена, Сумма) или кухонный компактный вид |
| **Удаление полей** | Сбоило из-за потери фокуса `ListBox` | Кнопка «❌» прямо на строке каждого поля и у каждого подполя |
| **Пунктирные строки** | Отсутствовали | Поддержка `Dashed`, `Solid`, `Dotted`, `Stars`, `Double` в GDI, ESC/POS и PDF |
| **Отступы между строками** | Не настраивались | Свойство `LineSpacing` (отступ снизу в pt) у любого поля + пустые строки `space.empty` |
| **Выравнивание в 2 колонки** | Только одно общее выравнивание | Флаг `IsRow` («В 2 колонки: значение справа») для строк «Заказ принят: 14:00», «Итого: 100.00» |
| **Сброс к дефолту** | Нельзя было вернуть вид шаблона | Кнопки «🔄 Накладная 58мм» и «🔄 Кухня 80мм» в редакторе |
| **Надежность печати** | Сбои при null Slip или путях Program Files | Безопасная работа с `%AppData%` и защита от сбоев |

## 🎨 Настройка кастомного чека 1-в-1 как в default шаблоне

Теперь кастомный чек можно настроить **полностью идентично** встроенному шаблону накладной или кухни.

### Быстрый способ (1 клик):
1. Откройте окно **«⚙️ Настроить поля»**.
2. В правой панели нажмите кнопку **«🔄 Накладная 58мм»** или **«🔄 Кухня 80мм»**.
3. Редактор мгновенно заполнит структуру чека всеми стандартными полями, звездочками, двухколоночными строками и блоком таблицы товаров.
4. При необходимости скорректируйте любые поля или удалите ненужные кнопкой «❌».
5. Нажмите **«Сохранить»**.

### Ручная сборка накладной как в default шаблоне:
1. `*** [Строка звёздочек]` (`separator.stars`)
2. Реквизиты продавца: `order.seller_title`, `order.seller_name`, `order.seller_inn`
3. `*** [Строка звёздочек]` (`separator.stars`)
4. Отступ: `space.empty` (LineSpacing = 4)
5. Заголовок: `НАКЛАДНАЯ / INVOICE` (`static.text`, Размер 2, Жирный, Центр)
6. Номер: `order.number` (`Заказ № / Order #`, Размер 2, Жирный, Центр)
7. Грузоотправитель и грузополучатель: `order.seller_title`, `shipping.first_name`, `billing.phone`
8. Двухколоночные строки (установить галочку **«В 2 колонки»**):
   - `Заказ принят:` (`order.date_created`)
   - `Накладная оформлена:` (`order.date_created`)
   - `Время доставки:` (`order.delivery_time`)
   - `Заказ доставлен:` (`order.delivered_at`)
9. Разделитель: `--- [Пунктирная строка]` (`separator.dashed`)
10. `📦 [Блок: Список товаров]` (`block.items`, Режим: `Таблица (как в накладной)`)
11. Итого: `order.total` (`Итого к оплате:`, В 2 колонки, Жирный)
12. Разделитель: `--- [Пунктирная строка]` (`separator.dashed`)
13. Оплата: `order.payment_method_title` (В 2 колонки)
14. Подписи: `order.sign_released`, `order.sign_received`
15. Комментарий: `order.customer_note`
16. Доставка: `order.delivery_type` (Размер 2, Жирный)
17. Подвал: `order.currency_note`, `order.footer` (Центр)

## 🏗 Архитектура решения

Решение состоит из следующих проектов в `WebApplication1.sln`:

1. **`PrintingSlips`** (Class Library, `net9.0-windows`):
   - `Models/`: модели чека (`Slip`, `SlipItem`, `ReceiptField`, `PrintTextLine`, `PrinterDestination`).
   - `Services/PrintDocumentBuilder.cs`: генерация ESC/POS байтов и подстановка данных WooCommerce.
   - `Services/PrintDocumentBuilder.Lines.cs`: разметка печатных линий для Windows GDI очереди.
   - `Services/WindowsQueuePrinter.cs`: печать через `System.Drawing.Printing.PrintDocument` с учетом настроек драйвера XPrinter, шрифтов и аппаратного отрезчика.
   - `Services/PdfSlipExporter.cs`: экспорт чеков в PDF через библиотеку `QuestPDF`.
   - `Services/PrintingService.cs`: координатор печати на очереди Windows и экспорта PDF.
   - `Services/WooCommerceService.cs`: опрос WooCommerce REST API по протоколу HTTPS.

2. **`ApplicationView`** (WPF Application, `net9.0-windows`):
   - `MainWindow.xaml`: главное окно управления сайтами, лентой заказов, списком принтеров и ручной печатью.
   - `ReceiptSettingsWindow.xaml`: визуальный конструктор структуры чека для каждого принтера.
   - `CompanySettingsWindow.xaml`: окно ввода реквизитов организации (ИНН, менеджер, подписи).
   - `AddNetworkPrinterWindow.xaml`: диалог добавления сетевого IP-принтера.
   - `Services/ProcessingData.cs`: сохранение и загрузка настроек JSON в `%AppData%\PrintingSlips`.

3. **`WebAPI`** (ASP.NET Core Web API / CLI test):
   - Инструмент прямого тестирования связи с сайтом WooCommerce.

4. **`ConsoleTest`** (Console Application):
   - Консольная утилита проверки структуры JSON ответов.

## 🛠 Установка, настройка и работа с проектом

### Требования
- Компьютер с **Windows 10 / 11** (x64)
- **.NET 9.0 Desktop Runtime** или **.NET 9.0 SDK**
- Установленный драйвер **XPrinter Driver 7.77**

### Сборка и запуск
1. Откройте `WebApplication1.sln` в Visual Studio 2022+ или выполните в консоли:
   ```bash
   dotnet build WebApplication1.sln -c Release
   ```
2. Запустите проект `ApplicationView`:
   ```bash
   dotnet run --project ApplicationView/ApplicationView.csproj -c Release
   ```

### Первый запуск и настройка
1. **Добавление сайта WooCommerce:**
   - В левой панели введите адрес сайта (например, `https://myshop.ru`), `Consumer Key` (`ck_...`) и `Consumer Secret` (`cs_...`).
   - Нажмите **«Добавить»**.
2. **Настройка принтеров:**
   - В правом нижнем блоке отметьте галочками подключенные принтеры.
   - Для USB-принтера выберите тип подключения `Windows` и укажите ширину `58` мм.
   - Для кухонного IP-принтера укажите тип `Network` или установите его как сетевую очередь Windows и задайте ширину `80` мм.
3. **Настройка реквизитов компании:**
   - Нажмите **«Реквизиты продавца»**, заполните название, ИНН, ФИО и подписи.
4. **Настройка чека:**
   - Нажмите **«⚙️ Настроить поля»**.
   - Выберите принтер вверху, настройте или сбросьте шаблон кнопкой «🔄 Накладная 58мм» / «🔄 Кухня 80мм».
   - Нажмите **«Сохранить»**.
5. **Запуск автоматического мониторинга:**
   - Отметьте галочку **«Печатать чеки автоматически при поступлении заказа»**.
   - Укажите интервал опроса (1-5 минут).
   - Нажмите кнопку **«Запустить опрос»**. Статус службы станет зеленым: `Активен (Опрос...)`.

## 🖨 Настройка принтеров XPrinter (XP-58C и XP-80C)

1. Установите драйвер **XPrinter Driver v7.77** (Windows 10).
2. При установке выберите:
   - Для кассового принтера: **Printer Type:** `XP-58`, **Series:** `XP-58C` (с отрезчиком). Порт: `USB001`.
   - Для кухонного принтера: **Printer Type:** `XP-80`, **Series:** `XP-80C` (с отрезчиком). Порт: `TCP/IP` (или Tools NET).
3. В свойствах принтера в Windows (Устройства и принтеры -> Свойства принтера -> Параметры устройства):
   - Отрезка бумаги: `Перед печатью` или `После страницы / документа`.
4. Для проверки нажмите кнопку **«Тест печати»** в программе — на принтер уйдет тестовый чек с проверкой русского/английского текста, шрифтов и срабатывания ножа отрезчика.

## 💾 Структура шаблонов JSON

Шаблоны чеков сохраняются в системную директорию пользователя:
`%AppData%\PrintingSlips\Templates\{Имя_Принтера}.json`

Пример элемента разметки в JSON:
```json
{
  "Name": "Заказ принят:",
  "Key": "order.date_created",
  "CustomText": "",
  "FontSize": 1,
  "IsBold": false,
  "Align": "Left",
  "IsSeparator": false,
  "SeparatorStyle": "Dashed",
  "LineSpacing": 2,
  "IsRow": true,
  "ItemDisplayMode": "Table"
}
```

Все изменения проверены, совместимы со старыми конфигурациями и полностью поддерживают печать пречеков и кухонных чеков по ТЗ.
